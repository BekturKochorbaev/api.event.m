# EventM — генератор презентаций событий

Демо в духе gamma.ai: пользователь отвечает на 6 вопросов, выбирает шаблон
слайдов, и API возвращает две готовые картинки-слайда.

## Запуск

```bash
cp .env.example .env          # OPENAI_API_KEY можно оставить пустым
../.venv/bin/python manage.py migrate
../.venv/bin/python manage.py runserver
```

Без `OPENAI_API_KEY` включается `DEMO_MODE`: вместо обращений к OpenAI
рисуется каркас макета по реальным координатам. Весь поток работает целиком,
денег не стоит и интернета не требует.

## API

| Метод | URL | |
|---|---|---|
| GET | `/api/questions/` | вопросы и варианты ответов для формы |
| GET | `/api/templates/` | `template-1`, `template-2`, `template-3` |
| POST | `/api/generations/` | бриф + шаблон → `201 {id, status: "pending"}` |
| GET | `/api/generations/{id}/` | статус и ссылки на картинки |

POST не ждёт генерацию — она идёт в фоне, клиент опрашивает GET раз в пару
секунд, пока `status` не станет `done` или `failed`.

```bash
curl -X POST localhost:8000/api/generations/ \
  -H 'Content-Type: application/json' \
  -d '{"template_id":"template-1","answers":{
        "event_type":"product_presentation",
        "goals":["sales","press"],
        "emotion":"pride",
        "brand_attributes":["premium","modern"],
        "reference":"apple",
        "scale":"national"}}'
```

## Как устроена генерация

Шаблоны — статические JSON в [`template/`](template/), по файлу на страницу
(`template<N>-<страница>.json`). Каждый описывает слайд: элементы, координаты в
системе 100×100, типографику, стиль.

На каждую страницу выполняются две стадии:

1. **Копирайт** ([`services/copywriter.py`](app/services/copywriter.py)) —
   текстовая модель получает бриф и список элементов с лимитами по символам
   (лимит считается из площади бокса и кегля), возвращает плоскую карту
   `{id: текст}`. Макет модели не отдаётся вообще, так что испортить его она не
   может — текст вмерживается локально.

2. **Картинка** ([`services/zone_prompt.py`](app/services/zone_prompt.py)) —
   заполненный макет переводится в короткий зонный бриф: элементы группируются
   в `TOP` / `LEFT SIDE` / `RIGHT SIDE` / `BOTTOM` по геометрии, тексты
   цитируются дословно, типографика и палитра сводятся к паре фраз на слайд.
   Результат идёт в `gpt-image-1`.

   Зоны выводятся из координат, а не задаются руками: широкий блок в верхней
   полосе становится `TOP`, но только если сбоку от него ничего нет — иначе
   это верх колонки, а не полоса через слайд (`stands_alone()`).

### Почему зоны, а не координаты

Первая версия ([`prompt_builder.py`](app/services/prompt_builder.py), доступна
через `IMAGE_PROMPT_STYLE=detailed`) описывала каждый элемент отдельно с
процентами. Это давало промпт на 4500 символов, и `gpt-image-1` вёл себя с ним
плохо: бокс на `x=2` он понимал буквально и ставил первую букву на границу
кадра — она срезалась. Инструкции про отступ он игнорировал независимо от того,
в начале промпта они стояли или в конце.

Зонный бриф короче в 2.6 раза (1700 символов) и не содержит чисел, поэтому
модель применяет собственное чувство композиции вместе с нормальными полями.
На боевой проверке обрезка пропала на обеих страницах шаблона, где раньше
воспроизводилась стабильно.

Расплата — точность макета: шаблон стал описанием композиции, а не чертежом.
Точные координаты не потеряны, они лежат в `GeneratedImage.filled_layout` и
пригодятся детерминированному рендеру.

Оба промежуточных результата сохраняются в `GeneratedImage.filled_layout` и
`.prompt_used` — без них невозможно понять, кривой слайд из-за макета,
копирайта или промпта.

### Что остаётся нерешённым

Опечатки в кириллице. `gpt-image-1` иногда путает буквы («СОТРУДНИЧЕССТВА»)
и подмешивает латиницу в вордмарк. Зонный промпт снизил частоту, но не убрал
её — это ограничение модели.

Гарантированно лечится только детерминированным рендером: фон и фотография от
`gpt-image-1`, а текст накладывается локально по координатам из
`filled_layout`. Точка расширения — `generate_page()` в
[`services/generator.py`](app/services/generator.py).

## Фон

Генерация уходит в `threading.Thread`. Для демо этого достаточно. Если
понадобится переживать перезапуск — `run_generation(generation_id)` уже
самодостаточная задача, адресуемая по id, и меняется на Celery-таску без
правок логики.
